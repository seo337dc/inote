사용자가 세션을 닫거나 다른 작업으로 옮기려는 상태다. 목적은 **다음 세션(다른 PC 포함)이 파일만 읽고 이어 갈 수 있게 하는 것**이다. 아래 순서를 따른다. CLAUDE.md의 규칙이 우선이다. 배경은 [ADR 0008](../../../docs/adr/0008-direction-and-working-model.md)이다.

**실행 규칙**: git 명령은 한 단계씩 실행하고 결과를 확인한다. 삭제·되돌리기는 사용자 승인 후에만 한다.

## 1. 현황 점검 (읽기 전용)
`start` 스킬 2단계의 점검 명령을 그대로 실행한다(세 레포의 브랜치, 미커밋 파일, 병합 여부, origin/main보다 앞선 커밋, 로컬 main 이상, PR, worktree). 결과를 레포별 한 줄로 요약하고 **위험 신호를 먼저** 보여준다.
- 미커밋 파일이 있다 → 어떤 파일인지, 이번 작업의 것인지 묻는다.
- push 안 한 커밋이 있다(`git log origin/<브랜치>..HEAD`, 또는 upstream이 없으면 origin/main보다 앞선 커밋) → 알린다.
- 이미 병합된 브랜치 위에 커밋이 있다, 로컬 `main`에 직접 커밋한 흔적이 있다 → 알리고 옮길 방법을 제안한다(승인 후 실행).
- `gh`가 `seo-dongchan`이면 PR 상태가 비어 보일 수 있다고 덧붙인다.

## 2. 작업 지시서를 갱신한다
이번 세션의 작업 지시서 `inote/docs/todo/<기능>.md`를 찾는다. 없으면 만들지 묻는다(`start` 5단계 템플릿).
- **한 일**: `git log origin/main..HEAD --oneline`(레포별)과 `git diff --stat origin/main`으로 이번에 실제로 바뀐 것을 쓴다. 기억이 아니라 git에서 가져온다.
- **다음 할 일**, **막힌 것·결정 대기**: 이번 세션에서 나온 것을 체크박스로 적는다. 사람이 정해야 하는 것은 그렇게 표시한다.
- **다시 시작하는 법**: 브랜치 이름(레포별)과 먼저 확인할 명령(예: 테스트 실행)을 한두 줄로 적는다.
- 수정안을 보여주고 **승인받은 뒤** 반영한다.

## 3. 기능이 끝났는지 판단한다
끝났다고 보려면 (a) PR이 병합됐고 (b) 지시서의 "다음 할 일"이 모두 체크됐거나 백로그로 옮겨졌다. 끝나지 않았으면 이 단계는 건너뛰고 4단계로 간다.
끝났다면 순서대로 사용자에게 제안한다(각각 승인받고 한다).
1. **포트폴리오 후보 점검** — 이력서·포트폴리오에 쓸 만한 것(측정 가능한 개선, 구조 결정, 원인을 파고든 버그)이 있는지 후보를 보여준다. 승인하면 `portfolio-recorder` 에이전트를 부른다. 브리핑에 목표, 자료(지시서·devlog·PR·코드 경로), 하지 말 것(`docs/portfolio/` 밖 수정·커밋·삭제), 출력 형식을 쓴다(에이전트는 대화 맥락이 없다). 보고서의 파일·`파일:줄` 근거를 직접 확인하고, "확인 필요"로 남긴 항목은 사용자에게 그대로 전한다.
2. **미룬 일을 백로그로** — 지시서에 남은 "다음 할 일" 중 이번에 안 하기로 한 것은 `docs/todo/backlog.md`에 옮긴다(출처 표기, 가치 없는 것은 옮기지 않는다).
3. **지시서 삭제** — 위 둘이 끝나면 지시서를 삭제할지 묻는다(진행 중 문서는 끝나면 지운다). 그 파일을 가리키는 다른 문서의 링크가 있으면 같이 고친다(`grep`으로 확인).
4. **CLAUDE.md의 사실 점검** — 이번 작업으로 CLAUDE.md·README에 적힌 사실(구조·규칙·상태)이 바뀌었는지 보고, 바뀌었으면 알린다.
5. **블로그 거리** — 사이트 글로 쓸 만한 문제·결정이 있으면 한 줄로 제안만 한다(쓰지 않는다).

## 4. 정리할 것을 제안한다
- 이미 병합된 로컬·원격 브랜치와 더 이상 쓰지 않는 worktree를 **목록으로만** 보여준다. 삭제는 승인 후 한다.

## 5. 마무리 보고
- 레포별 상태(커밋·푸시 필요 여부), 갱신한 지시서 경로, 사용자가 할 일(예: PR 생성, 결정 대기)을 짧게 정리한다.
- **다음 세션 시작 문구**를 한 줄로 만들어 준다. 예: `docs/todo/<기능>.md를 읽고 이어서 진행해줘. 브랜치는 inote: feat/..., inote-server: feat/...`

## 하지 않는 것
- 커밋·push·PR 생성(필요하면 `/commit`을 안내한다).
- 승인 없는 삭제, 승인 없는 `main` 되돌리기.
- 사실을 지어내기(포트폴리오·지시서에 확인하지 못한 수치나 결과를 적지 않는다).
