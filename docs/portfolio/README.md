# 포트폴리오·이력서 기록

이력서·포트폴리오·면접 답변에 쓸 수 있도록, 끝낸 기능과 기술 결정을 모아 두는 곳이다. **학습 문서가 아니다**(개념 설명은 [`../learning/`](../learning/)).
새 항목은 [`portfolio-recorder`](../../.claude/agents/portfolio-recorder.md) 에이전트가 쓰거나 사람이 직접 쓴다. 기록은 항상 "코드·git·테스트로 확인한 사실" 기준이다.

## 기록 대상
새 기능 · 대안이 있었던 설계 결정 · 측정으로 보여 줄 수 있는 개선 · 원인을 파고든 버그 · 운영 안전 설계.
문구·스타일 수정, 문서 정리, 설정 변경은 기록하지 않는다.

## 상태 표기
- **개발 환경 검증** — 로컬 개발 DB·로컬 서비스에서 확인함
- **운영 반영** — 운영 배포까지 끝남 (운영 반영 전이면 이력서에 쓸 때 "구현"과 "운영"을 구분한다)

## 항목 템플릿
1. 한 줄 요약 / 기간·역할·레포·기술
1-1. 전체 동작 흐름 (구성 요소, 저장 위치, 흐름도 — 세부 설명보다 먼저 전체 그림을 보여 준다)
2. 배경과 문제 (수치 + 측정 환경)
3. 목표
4. 설계 결정과 이유 (고른 안, 버린 안, 누가 정했는지)
5. 구현 포인트
6. 결과와 측정 (출처·환경·한계)
7. 테스트·품질
8. 어려웠던 점과 해결
9. 한계·후속
10. 이력서 문장 후보 (문장마다 근거 절 표시)
11. 면접에서 설명할 포인트
12. 근거 (커밋·파일·문서)

## 쓰는 규칙
- 과장하지 않는다. 측정하지 않은 수치·영향은 쓰지 않고 "확인 필요"로 둔다. 측정 환경과 한계를 같이 적는다.
- 사용자가 직접 정한 것과 AI(Claude Code)와 함께 구현한 것을 구분한다.
- 비밀값·접속 주소·이메일, 실제 글의 제목·본문·id는 쓰지 않는다.
