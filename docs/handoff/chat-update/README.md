> 다른 PC·다른 세션에서 이어서 작업하기 위한 인수인계. **세 레포에 걸친 작업**이라 대표 문서를 `inote`에 둔다.
> 작성: 2026-10-23 (Claude Code) · 상태: **기획 완료·API 계약 승인됨, 구현 미착수**
> 결정과 계약의 **소스는 [`docs/adr/0006-chat-update.md`](../../adr/0006-chat-update.md)**. 이 폴더의 프롬프트와 내용이 어긋나면 ADR이 맞다.
> 후속으로 미룬 것은 [`docs/todo/chat-update.md`](../../todo/chat-update.md).

## 무엇을 만드나 (한 문단)
LLM 채팅을 "글쓰기 화면에서만 기록이 남는 조사용 채팅"에서 **저장되는 독립 채팅**으로 바꾼다. 채팅은 글에 연결할 수 있고(채팅 1개 : 글 1개, 한 글에 채팅 여러 개), 상세·글쓰기 화면에서 시작하면 그 글에 자동 연결된다. LLM이 현재 글 본문을 읽고, 편집 화면에서는 답변을 글 맨 아래에 추가할 수 있다. 채팅 이름은 AI가 첫 질문으로 한 번 짓고 사용자가 수정하며, 채팅은 삭제할 수 있다. 이미지·선택영역 AI 수정·말로 "넣어줘"는 후속.

## 배포 순서 (반드시 지킬 것)
1. `schema.sql` 변경을 **운영 Supabase(AI용)에 수동 적용** — AI 코드 배포 전
2. `inote-ai` 배포 (새 필드는 전부 옵션 → 구 FE가 그대로 동작해야 함)
3. `inote-server` 배포 (글 삭제 → `unlink-post`) — **FE 배포 전에 끝낸다**
4. FE 배포
5. `inote-ai`의 내부용 `DELETE /sessions/{id}` 제거 (별도 작업, 3번 배포 확인 후)

이유: FE가 먼저 나가면 새 세션(id ≠ postId)이 글 삭제 뒤에도 연결된 채로 남는다. 반대로 구 `inote-server`가 남아 있는 동안 내부용 `DELETE /sessions/{id}`를 먼저 지우면 글 삭제 연동이 깨지고, 지우지 않고 두면 옛 글 세션이 **삭제**되어 "글 삭제 시 미연결로 유지" 결정과 어긋난다 (옛 세션은 id가 곧 postId이므로).

## 병렬로 진행하는 방법
- 계약이 승인됐으므로 FE는 **MSW 목으로 먼저** 구현·테스트할 수 있다 (CLAUDE.md "계약 → FE → BE → 통합"). 다른 PC에서 `inote-ai`·`inote-server`를 작업하는 동안 FE를 진행해도 된다.
- 통합 테스트는 세 레포가 다 준비된 뒤, **로컬 개발 DB(도커 Postgres)에서만** 한다. 운영 DB 연결 금지.
- 운영 DB(Supabase) 스키마 적용은 **사용자가 직접 하거나 명시적으로 승인한 뒤에만** 한다. AI가 임의로 적용하지 않는다.

## 모든 세션 공통 규칙 (각 프롬프트에도 들어 있음)
- 세션 시작: `git pull` → 해당 레포의 `CLAUDE.md` → 이 폴더의 해당 문서 → ADR 0006
- 기획·UX·아키텍처를 AI가 임의로 결정하지 않는다. 계약과 다르게 하고 싶으면 멈추고 사용자에게 묻는다
- **커밋·PR·push는 사용자가 명시적으로 요청할 때만.** 커밋은 기능 단위로 쪼개고, 커밋할 때 PR description 초안도 함께 작성해 보여준다 (레포의 PR 템플릿 형식)
- 구현이 끝나면 결과만 보고하고 멈춘다. 다음 단계 진행 여부는 사람이 정한다
- 환경변수 값·시크릿을 채팅이나 문서에 붙이지 않는다
- 이 문서의 코드 위치(파일·줄)는 2026-10-23 조사 기준이다. **구현 전에 직접 다시 확인**한다

## 아직 열려 있는 것
- 본문 길이 상한 수치(약 15,000자는 제안값)와 Groq 요청 한도 확인
- 같은 본문을 요청 앞쪽에 두면 Groq 프롬프트 캐싱이 되는지 (확인 못 함)
- 신규 글(아직 id가 없는 작성 중)에서 시작한 채팅의 연결 시점 — `WritePostForm`·라우트 확인 필요
- 에디터에 프로그램이 삽입한 내용이 변경(dirty)으로 잡히는지 — `PostEditor` 확인 필요
- `inote-ai` 작업에도 "사람이 테스트를 직접 작성" 규칙을 적용할지 — `inote-ai` 작업 시작 때 사용자에게 묻는다
