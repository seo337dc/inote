# 프로젝트 방향과 작업 방식 (2026-11-13)

> 2026-10-28 `feature-backlog-and-direction.md`("목표 직무·프로젝트 방향 미정, 우선 기능부터")를 대체한다. 그 문서의 기능 후보는 [`docs/todo/backlog.md`](../todo/backlog.md)로 옮겼다.
> 이 문서의 내용은 모두 **사용자(2026-11-13)가 정한 것**이다. AI는 정리만 했고 새로 결정하지 않았다.
> 상태: 방향은 확정. 작업 방식은 문서 정리까지 적용 중이고 `start`·`wrap` 스킬은 아직 만들지 않았다(5절).

## 1. 방향 (결정)
- **방향은 풀스택**이다. 직업은 **FDE(Forward Deployed Engineer, 고객 현장에 투입돼 시스템을 연결·배포하는 엔지니어)** 쪽으로 살아날 것으로 본다(사용자의 판단).
- 2026-10-28에 열려 있던 질문 "(a) 백엔드·풀스택(LLM 연동 포함) / (b) 모델·ML 쪽 AI 엔지니어" 중 **(a)로 정한다.** LLM 연동 경험은 풀스택·FDE 경험의 일부로 쌓는다.
- `inote`는 세 가지를 겸한다.
  1. **포트폴리오** — 문제 → 결정 → 결과를 설명할 수 있는 기록을 남긴다.
  2. **개인용 앱** — 본인이 실제로 쓴다.
  3. **확장하는 학습장** — 모바일 앱(`apps/app`)과 인프라까지 직접 다뤄 경험과 실력을 쌓는다. 나중에 실제 제품이 될 수도 있다.
- 따라서 기능을 만들 때 "되는가"만이 아니라 **왜 그렇게 정했는지, 무엇을 겪었는지**가 남아야 한다(ADR·사이트 글·`docs/portfolio/`).

## 2. 작업 방식 (결정)
**워크스페이스는 하나다.** 세 레포(`inote`·`inote-server`·`inote-ai`, 곧 모바일)를 한 번에 열고 일한다. 레포마다 역할이 달라 문서를 따로 두던 방식은 이제 맞지 않는다.

| 문서 종류 | 질문 | 수명 | 위치 |
|---|---|---|---|
| 현재 상태 (README·구조) | 지금 어떻게 생겼나 | 항상 최신, 낡으면 고침 | 각 레포 |
| 결정 (ADR) | 왜 이렇게 정했나 | 확정되면 고치지 않음 | 여러 레포에 걸치면 `inote`, 한 레포 안이면 그 레포 |
| 운영 (runbook) | 배포·복구·디버깅은 어떻게 하나 | 절차가 바뀌면 갱신 | 각 레포 |
| 진행 중 (`docs/todo/`, handoff) | 지금 뭘 하고 있나 | **끝나면 삭제** | **`inote` 한 곳** |
| 발행 글 | 남에게 설명한다면 | 사이트에 올리면 md 삭제, `docs/blog/README.md`에 주소만 | 사이트 |
| 성과 기록 | 이력서에 쓸 결과 | 기능이 끝날 때 한 번 | `docs/portfolio/` |

- **진행 중 문서는 반드시 사라진다.** 지우기 전에 포트폴리오로 건질 것이 있는지 본다(`portfolio-recorder`).
- **"나중에 할 일"은 `docs/todo/backlog.md` 한 파일에만** 적고, 시작하면 `docs/todo/<기능>.md` 작업 지시서로 옮긴다. 기능마다 후속 파일을 만들지 않는다.
- **세션은 작업 하나에 하나.** 세션이 죽어도 작업 지시서 한 장이 인수인계가 된다. 프로젝트와 무관한 개념 학습은 레포에 md를 만들지 않고 별도 대화·사이트에서 한다. 병렬 작업은 `git worktree`로 폴더를 분리한다.
- **스킬은 반복되는 위험한 절차에만**, **에이전트는 독립적인 읽기 전용 검증에만** 쓴다. 새 스킬은 "같은 절차를 두 번 틀렸다"는 근거가 있을 때 만든다.

## 3. 검토했지만 택하지 않은 것
- **레포별로 문서를 따로 두는 기존 방식** — 워크스페이스가 하나가 된 뒤로 어느 레포에서 무엇을 읽어야 하는지 헷갈리고 같은 주제가 여러 곳에 중복됐다(호스팅·DB 이전 기록이 세 레포에 흩어져 있었다).
- **역할별(FE·BE·문서) 세션을 상시 분리** — 서로의 변경을 모른 채 진행돼 맞추는 일이 사람 몫이 된다.
- **서브에이전트·스킬을 먼저 많이 만들기** — 쓰이지 않거나 호출 순서가 사람 기억에 의존하는 것이 늘어난다. 지금 있는 에이전트도 실제 호출 빈도를 확인한 뒤 줄인다.

## 4. 이 결정의 근거(사실)
- 2026-11-13 기준 문서가 세 레포에 약 70개였고, 최근 30일 커밋에서 docs가 feat보다 많았다(docs 46 · feat 26).
- 진행 중 성격의 문서(`todo` 22개, `handoff` 8개)가 끝난 뒤에도 남아 있었고, 일부는 병합된 PR과 어긋난 상태였다(예: `admin-embeddings.md`가 BE 미완료로 적혀 있는데 `inote-server` PR #17은 이미 병합).
