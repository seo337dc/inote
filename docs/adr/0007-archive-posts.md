## 1. 요구사항 (사용자)
1. 글이 너무 많아 목록이 길다. **삭제는 하고 싶지 않고**, 메일의 보관처럼 **목록에서 보이지 않게** 하고 싶다.
2. **글 목록**과 **나의 글**에서는 보이지 않는다.
3. 보관한 글을 **따로 볼 수 있는 화면**(보관함)이 있다.
4. 보관한 글은 **주소로 직접 접근하면 작성자만** 볼 수 있다.

## 4. 데이터
`Post`에 **`archivedAt DateTime?`** 하나를 추가한다.
- `null` = 일반 글, 값이 있으면 보관한 시각(보관함 정렬·표시에 쓴다).
- 컬럼 추가만 하는 마이그레이션이라 기존 글에 영향이 없고 기본값이 필요 없다(`null`).
- `isPrivate`(공개 범위)와 **별개 축**이다. 비공개 글도 보관할 수 있고, 해제하면 원래 공개 상태로 돌아온다.

## 5. API 계약 (제안 — 승인 필요)

### 보관 / 보관 해제 (로그인 필요, 본인 글만)
| 대상 | 계약 |
|---|---|
| 보관 | `POST /blog/posts/archive` `{ ids: string[] }` (1~100개) → `200 { archivedIds: string[] }` |
| 보관 해제 | `POST /blog/posts/unarchive` `{ ids: string[] }` (1~100개) → `200 { unarchivedIds: string[] }` |

- **본인 글이 아니거나, 없거나, 발행 전(draft)인 id는 조용히 건너뛴다**(오류 아님). 응답의 `archivedIds`로 실제 처리된 것만 알려준다. 남의 글 id를 보내도 그 존재 여부를 알 수 없다.
- 이미 보관된 글을 다시 보관하면 **멱등**(시각을 바꾸지 않고 응답에는 포함).
- 보관할 때 `pinned`는 `false`로 바꾼다(3절 B).
- 같은 이름 충돌을 피하려고 `:id`를 쓰는 기존 경로(`/blog/posts/:id`)보다 **먼저** 선언한다(`archive`가 id로 해석되지 않게).

### 목록 조회
| 대상 | 계약 |
|---|---|
| 나의 글 | `GET /blog/posts/mine` — **보관한 글을 제외**(기본). 응답 모양 그대로 |
| 보관함 | `GET /blog/posts/mine?archived=true` — **보관한 글만**, `archivedAt` **최신순**. 응답 모양은 나의 글과 같고(`items`/`total`/페이지/`categoryCounts`), 카테고리·검색 쿼리도 그대로 받는다. **`categoryCounts`는 보관한 글 기준으로 센다**(보관함의 카테고리 필터가 보관 글 수를 보여준다). 나의 글의 `categoryCounts`는 보관 글을 뺀 값 |
| 글 목록(홈)·작성자별 | `GET /blog/posts` — 보관한 글 **제외** (쿼리 변화 없음) |

### 글 상세
- `GET /blog/posts/:id`: 보관한 글은 **작성자만** 200, **다른 사람(비로그인 포함)은 404**.
- 응답의 글 객체에 **`archivedAt: string | null`** 이 추가된다(FE 타입도 같다).

## 7. 에디터·FE (제안)
- **나의 글(`/my-posts`)**: 헤더 위에 `[나의 글 | 보관함]` 전환. 보관함은 **`/my-posts/archive`** 경로로 두고 같은 화면 컴포넌트(`MyPostsPage`)에 `archived`만 넘겨 재사용한다 — 검색·카테고리 필터·페이지 링크가 `basePath`만 바꾸면 그대로 동작한다. (처음에는 `?view=archive` 쿼리로 구상했지만, 경로로 나누는 편이 링크·필터를 건드리지 않아 더 단순해서 바꿨다 — FE 구현 중 변경)
- **선택 모드**: 목록에서 여러 글을 골라 **[보관]**(나의 글) / **[보관 해제]**(보관함). 기존 "글 이동" 탭의 다중 선택 UI를 재사용할 수 있는지 FE 단계에서 확인한다.
- **글 상세(내 글)**: **[보관하기]** / **[보관 해제]** 버튼. 보관한 글은 상단에 "보관된 글입니다(작성자만 볼 수 있어요)" 안내.
- **카테고리 사이드 필터**: 보관한 글은 개수에서 빠진 값을 그대로 보여준다(BE가 계산).
- 보관/해제 후 `my-posts`·`posts`·카테고리 개수·글 상세 쿼리 캐시를 무효화한다.
- 보관함이 비었을 때 빈 상태 안내("보관한 글이 없어요").

## 10. 구현하면서 계약에 보탠 것 (2026-10-27, BE)
승인된 계약(3~6절)은 그대로이고, BE 구현 중 빈틈이 보여 아래를 더했다.

| 항목 | 내용 | 이유 |
|---|---|---|
| 비슷한 글(`GET /blog/posts/:id/similar`)의 **원본 글** | 보관한 글이 원본이면 작성자 외에는 404 | 상세는 작성자만 열 수 있는데 이쪽이 열려 있으면 보관한 글의 존재가 드러난다. 후보 목록에서 보관 글을 빼는 일은 여전히 보류(3절 G) |
| 보관한 글을 **수정 저장**할 때 | `pinned: true`가 와도 고정되지 않는다(`false`로 저장). 보관 상태(`archivedAt`)는 수정으로 바뀌지 않는다 | 보관할 때 풀린 고정이 수정 저장으로 다시 켜지면 보관함의 고정 영역에 글이 나온다. `archivedAt`은 DTO에 없어 `whitelist`가 걸러낸다 |
| 보관·해제 **응답 코드** | `200` | 계약(5절)이 200이라 Nest의 POST 기본값(201)을 `@HttpCode(200)`으로 맞췄다 |
| **공개 글 id 목록**(`GET /blog/posts/public-ids`) | 보관한 글 제외 | 6절 #6. 임베딩 후보 함수(`embedding-candidates.ts`)는 건드리지 않고 이 서비스 메서드에서만 뺐다 |
| 마이그레이션 | `20261027000000_add_post_archived_at` — `Post.archivedAt TIMESTAMP(3)` 추가만 | 기본값 없음, 기존 글은 모두 `null`이라 배포 전후로 기존 코드에 영향이 없다 |
