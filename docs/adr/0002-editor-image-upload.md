# 에디터 이미지 업로드 — 설계·계약 초안

> 2026-10-21 작성. **계약(API)·키 구조는 사용자 승인 전 초안**이다. 승인되기 전에는 코드에 손대지 않는다.
> 진행 순서는 `CLAUDE.md`의 원칙대로 **계약 → FE → BE(테스트는 사용자가 작성) → 통합**.
> 이번에 하지 않고 남긴 것은 [`docs/todo/editor-image-upload.md`](../todo/editor-image-upload.md)에 기록한다.
> 배경: R2 고아 파일 설계 `docs/blog/image-upload-r2-orphan-files.md` (tmp 폴더 → 저장 때 승격, 참조 기반 정리)

## 1. 요구사항 (사용자)
1. 에디터에서 **커서 위치에** 이미지를 올려 넣는다.
2. 글쓰기·수정 중에는 **우선 `tmp`에 올려 두고**, **저장하면 글(post)로 옮긴다.**
3. 이미지 크기를 **노션처럼 끌어서 늘리고 줄인다.**

## 2. 결정 (2026-10-21 사용자 승인)
| 항목 | 결정 | 택하지 않은 안 |
|---|---|---|
| 승격 시점 | **저장(발행) 때만.** 자동 임시저장(1.5초)은 tmp URL 그대로 둔다 | 자동저장마다 승격 |
| 크기 저장 | **본문 폭 대비 비율(%)** — `style="width: 60%"` | 픽셀(px) |
| 적용 범위 | **글쓰기 에디터만** | 독서 기록 에디터까지 |
| 고아 파일 정리 배치 | **이번엔 제외**, 후속으로 | 같이 구현 |

## 3. 전체 흐름

```
[에디터]  이미지 선택/붙여넣기/드롭
   → 커서 위치에 자리표시 노드 삽입 (업로드 중)
   → POST /uploads/post-image  → R2 tmp/post/<userId>/<uuid>.<ext>
   → 노드의 src를 tmp 공개 URL로 교체 (크기 핸들로 width % 조절)
   → (1.5초마다) 자동 임시저장: content에 tmp URL이 그대로 들어감

[저장(발행)]  PATCH /blog/posts/:id { publish: true, content: "...<img src=tmp URL>..." }
   → BE: content의 <img src> 중 "내 tmp 폴더" 주소만 찾아
         R2에서 post/<userId>/<postId>/<uuid>.<ext> 로 복사 → src를 새 주소로 바꿔 content 저장
         → 복사에 성공한 tmp 원본은 삭제
```

## 4. R2 키 구조 (제안 — 승인 필요)
```
업로드    tmp/post/<userId>/<uuid>.<확장자>
저장 후   post/<userId>/<postId>/<uuid>.<확장자>
```
- `<확장자>`는 사용자 파일명이 아니라 **검증된 MIME**(jpeg/png/webp/gif)에서 정한다.
- `postId`를 폴더에 넣는 이유: 글을 지울 때 `post/<userId>/<postId>/` **접두어로 한 번에** 지울 수 있다(후속). `reading/<userId>/<uuid>` 규칙과 다르지만 글은 이미지가 여러 장이라 묶는 편이 낫다.
- 기존 `uploads/<userId>/...`(글 썸네일·독서 표지)는 **그대로 둔다.**

## 5. API 계약 (제안 — 승인 필요)

| 대상 | 계약 |
|---|---|
| 업로드 | `POST /uploads/post-image` (multipart `file`, 로그인 필요) → `201 { url }`. 5MB 이하, jpeg/png/webp/gif만(매직 넘버 검증, 기존 `uploads/image`와 같은 규칙). 키는 위 `tmp/post/<userId>/<uuid>.<ext>` |
| 저장 승격 | `PATCH /blog/posts/:id` (기존) — `publish: true`일 때 `content`의 `<img src>`를 훑어 **내 tmp 폴더 주소만** 승격한다. 응답의 `content`는 **바뀐 주소가 반영된 값**이다 |
| 자동 임시저장 | `publish` 없음 → **승격하지 않는다.** content는 그대로 저장 |

승격 규칙 (BE)
- 대상: `src`가 `<CF_R2_PUBLIC_URL>/tmp/post/<요청자 userId>/<파일>` 인 것만.
- **남의 tmp 폴더 주소, 외부 URL, 이미 `post/...`인 주소는 건드리지 않는다**(오류도 아님). 남의 tmp 파일을 자기 글로 가져오는 것을 막는다.
- 같은 이미지가 content에 여러 번 나와도 한 번만 복사하고 모든 `src`를 바꾼다.
- **복사가 실패하면 저장을 막지 않는다**(fail-open): 그 이미지는 tmp 주소 그대로 두고 저장한 뒤 경고 로그를 남긴다. 사용자의 글 저장이 이미지 문제로 실패하는 것이 더 나쁘다. 다음 저장 때 다시 시도된다.
- 복사에 성공한 것만 tmp 원본을 지운다(실패하면 지우지 않음).

## 6. 에디터 FE (제안)
- **이미지 노드**: `@tiptap/extension-image`(v3, 의존성 추가)를 확장해 `width` 속성(예: `60%`)과 리사이즈 NodeView를 둔다. 저장 형태는 `<img src="…" style="width: 60%">`. 보여줄 때는 `max-width: 100%; height: auto`.
- **넣는 방법**: 툴바 **[이미지]** 버튼(파일 선택) + 슬래시 **`/이미지`** + **클립보드 붙여넣기** + **드래그 앤 드롭**. 모두 **커서(또는 놓은) 위치**에 삽입.
- **업로드 중**: 자리표시(미리보기)를 먼저 넣고, 성공하면 `src`를 tmp URL로 교체. **실패하면 노드를 지우고** 안내(크기 5MB 초과·형식 불가 등은 올리기 전에 막는다).
- **크기 조절(노션 방식)**: 이미지를 선택하면 **오른쪽 가장자리**에 핸들이 나타나고(왼쪽 정렬 고정이라 왼쪽 핸들은 두지 않는다), **드래그하면 본문 폭 대비 %로 크기가 바뀐다**(10%~100%, 가운데 기준이 아니라 왼쪽 정렬 고정). 놓으면 확정.
- 이미지 선택 후 `Backspace`/`Delete`로 삭제(기본 동작).
- 읽기 화면은 `dangerouslySetInnerHTML`로 그대로 그려서 `style="width: 60%"`가 그대로 적용된다.

## 7. 단계 (각 단계 끝에 멈추고 확인)
1. **계약 승인** ← 지금. 이 문서의 4·5·6절.
2. **FE**: 이미지 노드·리사이즈·삽입 경로 4가지·업로드 상태(MSW로 업로드 API를 흉내). 단위 테스트(비율 계산, 업로드 성공·실패 처리).
3. **BE**: `POST /uploads/post-image`, `R2Service`에 복사·삭제 추가, 저장 시 승격. **테스트는 사용자가 작성**.
4. **통합**: 개발 환경에서 올리기 → 임시저장 → 저장(승격) → 다시 열어 크기가 유지되는지.
5. 남긴 것은 `docs/todo/editor-image-upload.md`에서 다음 작업으로.

## 8. 열린 질문
- `postId`를 영구 키에 넣을지(제안: 넣음) — 승인 필요.
- 승격 복사 실패를 fail-open으로 둘지(제안: fail-open).
- `<img>` 파싱을 정규식으로 할지 가벼운 HTML 파서를 쓸지 — BE 단계에서 정한다.
