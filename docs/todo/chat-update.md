# 할 일 — LLM 채팅 업데이트 후속 (inote)

> 2026-10-23 채팅 업데이트 기획에서 **1차 범위에서 일부러 뺀 것**. 사용자가 "후속"으로 정했다.
> 1차 범위(세션 구조 개편, 글 읽기, "글에 넣기", 이름 수정·삭제)는 기획 확정 후 별도 문서에 둔다.

## 남긴 것
- [ ] **채팅 이미지 첨부 + AI 이미지 분석** — 비전 모델 가용성·품질(특히 한국어)이 가장 큰 변수라 마지막으로 미룸. 착수 전 Groq 문서로 비전 모델 확인부터. 이미지는 `inote-server`의 `/uploads/image`(R2)로 올리고 URL만 AI에 전달(Vercel 요청 본문 4.5MB 제한), 메시지에 URL을 jsonb로 저장해 다시 열어도 보이게. 이미지 첨부 요청에서만 비전 모델 사용, 평소엔 기존 모델 유지. 한도는 메시지당 3장·장당 5MB(안), 모델 한도 확인 후 확정
- [ ] **채팅에서 "넣어줘"라고 말하면 AI가 글에 넣기** — 1차는 답변마다 "글에 넣기" 버튼(글 맨 아래 추가). 말로 하는 방식은 `inote-ai`가 에디터 조작 명령(도구 호출)을 돌려주는 구조가 필요하고, 1차의 삽입 동작을 호출하는 형태로 얹는다
- [ ] **선택 영역 AI 수정** — 글에서 문단을 선택하고 "이 부분 간결하게"처럼 요청 → 제안을 보여주고 "적용/취소"로 승인. 1차는 전체 재작성 없이 선택 영역만 대상으로 한다는 방향만 정해둠. 제안 표시를 diff로 할지 미리보기로 할지 미정
- [ ] **채팅을 글 외 대상에 연결** — 할 일·독서·일지. 1차는 글만. 서버 모델은 `대상 종류 + 대상 id` 범용 구조로 만들어 두고 UI만 추가하면 됨(일지는 아직 "준비 중")
- [ ] **채팅 패널에서 글을 검색해 연결** — 1차는 글 화면에서 "이 글에 연결"/"연결 해제"만. 임의의 글을 골라 연결하려면 글 선택 UI와 권한 처리(남의 글 포함)가 필요
- [ ] **한 채팅을 여러 대상에 연결(N:M)** — 1차는 채팅 1개 : 대상 1개. 필요가 생기면 확장
- [ ] **`inote-ai`의 "초안 작성" 기능 정리 또는 활성화** — `/chat/stream`에 `can_draft=true`일 때 `start_draft` 도구로 AI가 글 초안을 스트리밍하는 서버 코드가 있으나(`draft_start`/`draft_text`/`draft_done`/`draft_failed` 이벤트), FE(`apps/web/src`)는 호출하지 않음(2026-10-23 검색 기준). 1차는 건드리지 않음. 후속에서 살려서 "AI가 글 써주기"로 확장할지, 쓰지 않으면 서버 코드를 정리할지 결정. 과거에 쓰다 뺀 이력인지는 git 로그로 확인 필요
- [ ] **채팅 API 인증** — `inote-ai`는 FE가 보낸 `user_id`를 그대로 신뢰한다. 1차에서 사용자용 삭제·이름 수정·연결 변경 API가 생기면 `user_id`를 위조해 남의 채팅을 지울 수 있는 영향이 커진다. 인증 검증(세션 토큰 확인 등) 도입을 별건으로 검토
- [ ] **LLM 답변을 에디터에 넣을 때 sanitize** — 1차는 Tiptap 스키마를 거치는 것만 믿는다. 상세 렌더(`PostArticle`)는 `dangerouslySetInnerHTML`로 sanitize 없이 출력하므로, LLM 출력이 HTML로 저장되는 경로가 생긴 만큼 별도 sanitize 필요 여부 검토
- [ ] **글 본문 전송 비용 최적화** — 1차는 매 메시지마다 최신 본문을 전송(길이 상한만 둠)
