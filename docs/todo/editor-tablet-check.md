# 에디터 태블릿 환경 기능 확인

> 2026-11-05 기록, 같은 날 분기 기준 갱신. 태블릿은 **지금까지 실제로 동작을 확인한 적이 없다.**
> 눈으로 본 것은 데스크톱과 폰 폭뿐이고, 그 사이 폭은 CSS 분기상 "아마 될 것"인 상태다.

## 현재 분기 기준 (2026-11-05 결정)
| 뷰포트 | 헤더 | 글 설정(카테고리·공개) | AI | 툴바 뒤쪽 버튼 |
|---|---|---|---|---|
| `sm` 미만 | 모바일 | 왼쪽 시트 | 하단 도크(⋮) | `…` 팝오버 |
| `sm`~`lg` 미만 | 모바일 | 왼쪽 시트 | 하단 도크(⋮) | 아이콘 펼침 |
| `lg`~`xl` 미만 (태블릿 가로 등) | **모바일** | **왼쪽 시트** | **오른쪽 고정 패널** | 아이콘 펼침 |
| `xl` 이상 | 데스크톱 | 왼쪽 패널 | 오른쪽 고정 패널 | 아이콘 펼침 |

- 헤더·글 설정은 `xl`(1280px), AI 패널·메모 버튼·`'/'로 블록 삽입` 문구는 `lg`(1024px), 툴바 `…` 접힘은 `sm`(640px) 기준이다.
- 이유: 상단 메뉴 + 글 설정 패널 + AI 패널이 한꺼번에 있으면 1024~1279px에서 에디터가 450~650px밖에 안 남아 툴바가 두 줄로 줄바꿈된다. 열을 줄여 에디터 폭을 확보한다. AI 패널은 에디터와 나란히 쓰는 기능이라 유지한다.

## 확인할 것
- [ ] **`lg`~`xl` (1024~1279px)**: `/write`에서 로고 중앙·왼쪽 `PanelLeft` 버튼으로 글 설정 시트가 열리는지, AI 패널이 오른쪽에 고정되는지, 툴바가 한 줄인지(1024px 근처는 빠듯함 — 두 줄이면 sticky 툴바가 본문을 가린다. `PostEditor.tsx`의 `SCROLL_PADDING.top`은 한 줄 기준)
- [ ] **헤더 전환이 전체 페이지에 적용된다**: 1024~1279px에서 홈·나의 글·글 상세도 모바일 헤더(☰ 시트)로 바뀐다. 특히 **나의 글**은 메뉴 시트의 카테고리 필터와 자체 사이드바(`lg` 기준)가 같이 보여 겹치지 않는지
- [ ] `sm`~`lg` (640~1023px): 툴바 아이콘이 한 줄에 들어가는지(펼친 툴바는 약 650px 필요 — 640px 근처에서 줄바꿈 여부), 두 줄이면 위와 같은 문제
- [ ] 슬래시(`/`) 블록 삽입 안내 문구를 `lg` 미만에서 숨긴 뒤 실제로 `/` 메뉴가 터치 키보드에서 뜨는지
- [ ] 모바일 도크(⋮ → AI·메모): 태블릿 폭에서 보이는 위치, 메모 하단 패널(60dvh) 크기가 적절한지
- [ ] 메모 패널: `lg` 미만은 하단 패널, 이상은 플로팅 패널이다. 태블릿에서 의도한 동작인지
- [ ] 터치로 표 편집 툴바·이미지 크기 조절·콜아웃이 되는지 (마우스 hover 전제 UI 점검)
- [ ] 터치 크기: 펼친 툴바의 아이콘 버튼(약 28px)이 팝오버 아이콘(40px)보다 작다. 터치 환경에서 펼친 툴바를 쓰는 폭(640px 이상)에서 누르기 어렵지 않은지
- [ ] 1024px 이상 태블릿(가로 모드, iPad Pro 등): AI 패널·플로팅 메모가 터치에서 깨지지 않는지

## 보류한 결정
- 툴바 접힘 기준을 뷰포트가 아닌 **툴바 영역의 실제 폭**(`ResizeObserver`, 약 640px 미만이면 `…`)으로 바꾸는 안. AI 패널이 열린 상태의 `lg`~`xl` 폭에서 툴바가 두 줄이 되는지 직접 본 뒤 정한다. 단점: 서버 렌더·첫 렌더에서 펼침↔접힘이 깜빡일 수 있다.
