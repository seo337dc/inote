# QA — 채팅 세션별 동시 진행 (2026-10-29)

> 대상 변경: `useChatMessages`가 메시지·전송 상태를 **세션별로** 보관 (브랜치 `feat/chat-concurrent-streams`, 미커밋).
> 자동 테스트(훅 4개)는 통과했고, **브라우저·실제 AI 서버로는 아직 확인하지 않았다.** 이 문서는 그 확인 목록이다.
> 결과는 아래 표의 체크박스와 메모에 적는다. 확인하지 못한 항목은 비워 두지 말고 "확인 못 함"이라고 적는다.

## 0. 준비 — 로컬 FE + 운영 BE·AI (2026-10-29 선택)
사용자가 `.env.local`을 운영 BE·AI 주소로 두고 **FE만 로컬(`pnpm dev`, 3011)** 로 실행하기로 했다. 로컬 개발 DB 환경(도커 DB·로컬 BE·AI)은 쓰지 않는다. 그래서 아래를 지킨다.

⚠️ **운영 데이터에 남는 것** — 로그인한 채로 채팅하면 대화가 **운영 AI DB에 저장**된다. 이 대화는 지금 FE에서 지우는 기능이 없다(ADR 0006에서 추가 예정).
- QA용 대화는 첫 질문에 `[QA]`를 붙여 나중에 알아보고 지울 수 있게 한다
- **글을 만들지 않는다** — 4-1·4-3은 `/write`에서 임시저장 글이 운영 DB에 생긴다. 하려면 확인 후 그 글을 직접 삭제한다
- 운영 AI 서버·Groq를 쓰므로 **6-1·6-2는 서버를 끌 수 없다** → 개발자 도구 Network의 Offline 또는 요청 차단으로 대신하고, 서버 종료와 다르다는 점을 결과 메모에 적는다
- 6-4(동시 3개 이상)는 운영 Groq 한도를 쓴다 — 개수는 3개까지만

| 순서 | 할 일 | 확인 |
|---|---|---|
| 1 | FE 실행: `cd apps/web && pnpm dev` (3011). 현재 `feat/chat-concurrent-streams` 브랜치 | http://localhost:3011 이 열림 |
| 2 | 개발자 도구 Network에서 채팅 요청이 **운영 AI 주소**(`.../chat/stream`)로 가는지, 주소에 `//`가 없는지 (이 브랜치에는 PR #19의 끝 `/` 방어가 없다) | 요청이 200으로 스트림됨 |
| 3 | 로그인 (이메일 또는 Google, 본인 운영 계정) | 채팅 패널에 대화 목록이 보임 |

답이 너무 빨리 끝나서 "진행 중" 구간을 만들기 어려우면, **길게 답하게 하는 질문**을 쓴다. 예: "도커와 쿠버네티스의 차이를 표와 예시를 곁들여 자세히 설명해줘".

## 결과 요약 (2026-10-29)
- **사용자 판단: QA 완료.** 로컬 FE + 운영 BE(로그인만) + 느리게 답하는 **가짜 AI 서버**(답 100조각, 약 15초)로 확인했다. 항목별 결과 칸은 채우지 않았다 — 어떤 항목을 직접 해봤는지는 기록이 없다.
- **서버 로그로 확인된 것**(가짜 서버 로그): 대화 A가 진행 중일 때 새 대화 B로 옮기고 B에도 질문을 보냈다. 두 답이 모두 끝까지 진행돼 `100/100`까지 저장됐고(A 1,615자, B 1,415자), FE가 연결을 끊었다는 로그는 없었다. 이전에는 B 전송이 막혔던 상황이다.
- 사용자 확인: "끊기지 않고 된 것 같다".
- **8번(대화 목록 붉은 점)**: 사용자가 가짜 AI 서버로 확인했다("확인했어"). 항목별(8-1~8-5) 결과는 기록하지 않았다.
- **확인하지 못했거나 별도 확인이 필요한 것**:
  - 가짜 서버는 실제 Groq의 청크 모양·지연과 다르다. 서버가 답을 저장하는 시점(스트림이 끝난 뒤)도 코드로 읽은 대로 흉내낸 것이라, 운영 서버로 한 번 확인이 필요하다 (1-5)
  - 6번(오류·한계)의 `[cut]`·`[bad]`·`[split]` 결과는 기록이 없다
  - 4번(`/write` 경로)과 5번(게스트·로그인 전환)은 확인 여부를 모른다
  - "A가 멈춘 것 같다"는 인상이 한 번 있었다. 서버 로그로는 멈추지 않았고, 대화 목록에 "답변 중" 표시가 없어 다른 대화에 있는 동안 진행이 보이지 않는 것이 원인일 수 있다 (표시는 아직 정하지 않음 — 아래 발견한 것)

- 다른 대화에 있는 동안 A가 진행 중인지 알 수 없다 (대화 목록에 "답변 중" 표시 없음). 이번 범위에서는 일부러 뺐고, 실제로 써 보니 "멈춘 것 같다"는 인상을 줄 수 있다 → 후속 여부는 사용자가 정한다
