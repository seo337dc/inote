# 할 일(Todo) 기능 기획 — 결정 기록

> 2026-10-12 사용자와 하나씩 의논해 정한 내용. **아직 코드로 구현된 것은 없다**(아래 "현재 코드 상태" 참고).
> 기획·UX는 AI가 임의로 정하지 않는다 — 여기 적힌 것만 확정이고, "남은 결정"은 사용자가 정한 뒤 반영한다.

## 배경

할 일은 성격이 다른 두 가지로 나뉜다.

1. **오늘 할 일** — 날마다 그날 할 일이 있다. 예: 독서, 이력서 수정, 회사 지원, 가계부 작성
2. **다른 할 일** — Jira 태스크 같은 느낌. 묶음(예: "사이드프로젝트") 아래 작업들이 있고 일정은 선택. 예: 할일 페이지 개발, DB 세팅, API 개발

지금 `/todos`는 이 둘을 구분하지 않는 평면 목록(제목 + 선택 마감일 + 완료 여부)이다.

## 확정된 결정

### 1. 오늘 할 일 = 루틴 + 그날 추가

- **루틴**: 독서·가계부 작성처럼 반복되는 항목을 한 번 등록하면 매일 오늘 목록에 자동으로 나타나고, 체크는 매일 새로 시작한다. 어제 무엇을 했는지 기록이 남는다. (※ 결정 14: 자동으로 나타나는 방식은 없어지고, 설정 화면의 고정 리스트를 오늘 카드로 복사해 오는 방식으로 바뀜)
- **그날 추가**: 그날만의 한시 항목(이력서 수정, 회사 지원 등)을 오늘 목록에 직접 추가한다.
- 검토했다가 택하지 않은 안: 날짜별 직접 입력만(반복 없음), 루틴만(그날 추가 없음).

### 2. 다른 할 일 = 묶음 > 작업, 3단계 상태

- 묶음(프로젝트) 아래에 작업이 있고, 작업의 **일정은 선택 사항**이다. (처음엔 날짜 하나였으나 2026-10-12에 **시작일·종료일**로 바뀜 — 결정 11)
- 작업 상태는 **할 일 / 진행 중 / 완료** 3단계. ~~묶음 안에서 상태별로 묶어 보여주는 목록~~ → **2026-10-12 변경: 상태별로 나눠 보여주지 않고 한 목록**이며, 카드 안에서 **끌어서 순서를 바꾼다**(결정 8 참고).
- 검토했다가 택하지 않은 안: 완료/미완료 체크만, 칸반 보드(드래그).

### 3. 화면 = 한 페이지 + 상단 탭 + 날짜 카드

- `/todos` 한 페이지에 **`[오늘의 할일 | 할 일]`** 탭(사용자가 정한 이름). 메뉴는 지금처럼 하나("할 일"). 페이지 제목도 "할 일"이라 두 번째 탭 이름과 겹친다 — 제목을 어떻게 할지는 정하지 않았다.
- **카드**: `inote-money`의 날짜 카드(스크린샷: 날짜(요일) 헤더 / 항목 줄 / 합계 줄)처럼 **하루가 카드 한 장**이고 안에 그날 항목이 줄로 들어간다. 합계 줄은 "N개 중 M개 완료" 같은 형태를 생각 중(문구 미확정).
- **카드 모양**: `inote` 톤에 맞춘 **얇은 회색 테두리 + 둥근 모서리, 그림자 없음**. (`inote-money`처럼 그림자 있는 카드는 택하지 않음 — 다른 inote 화면과 톤이 달라 보일 수 있어서)
- 이 날짜 카드 구조가 **"오늘의 할일" 탭**에 해당한다(작업 일정은 나오지 않는다 — 결정 10). **탭에는 오늘 카드 한 장만 보여준다**(2026-10-12 변경: 처음엔 오늘 카드 아래로 지난 날짜 카드가 쌓이는 안이었으나, 지난 기록은 별도 화면으로 분리하기로 함 — 결정 4).
- **"할 일" 탭**: **묶음 하나 = 카드 한 장, 작업은 카드 안.** 헤더에 묶음 이름, 안에 **한 목록의 작업 줄(상태 색상 뱃지 + 선택 일정, 끌어서 순서 변경 — 상태별 소제목·완료 접힘은 없음, 2026-10-12 변경)**, 아래 합계 줄에 "N개 중 M개 완료". 모든 묶음이 한 화면에 카드로 나열되고 별도 상세 페이지는 만들지 않는다. 카드 모양은 위와 같은 얇은 테두리 카드. (택하지 않은 안: 묶음 요약 카드 → 눌러서 묶음 상세 페이지로 이동)
- 헤더 틀은 홈과 같다: 폭 `max-w-3xl`, 제목 + 빨간 개수, 아래 회색 설명 한 줄, 입력줄은 목록 위에 유지.
- 검토했다가 택하지 않은 안: 한 페이지 위아래 두 영역, 메뉴 두 개로 분리(`/todos`, `/tasks`).

### 4. 안 끝난 "오늘 추가" 항목은 이월하지 않는다

- 하루가 지나면 그날 기록으로만 남고, 다음 날 오늘 탭은 새로 시작한다.
- **지난 기록은 별도 화면에서 본다.** "오늘의 할일" 탭에는 오늘 카드만 있다.
  - **들어가는 방법**: 오늘의 할일 탭 **상단(카드 위, 오른쪽)의 "지난 기록 보기 →" 링크**로 별도 페이지로 이동한다(2026-10-12: 처음엔 카드 아래였으나 위로 옮김). 탭은 `[오늘의 할일 | 할 일]` 2개 그대로. (탭을 3개로 늘리는 안은 택하지 않음)
  - **화면 모양**: **날짜 카드 목록, 최신순.** 위에서 정한 날짜 카드를 그대로 재사용해 어제부터 아래로 쌓고, [더 보기]로 이어서 불러온다. (달력에서 날짜를 눌러 보는 안은 택하지 않음)
  - **기간 보기(2026-10-12 추가)**: 지난 기록 화면 상단에 **`[전체 | 주차별 | 월별]` 탭**(`inote-money` 가계부의 달력/주차별/전체와 같은 틀). **전체** = 최신순 카드 + [더 보기](7일씩). **주차별** = `◀ 2026년 10월 ▶`로 달을 옮기고, 그 달 카드를 **"10월 N주차"로 묶어** 최신 주차부터(주차 제목 오른쪽에 "N개 중 M개 완료"). **월별** = 같은 달 이동, 그 달 카드를 주차 제목 없이 최신순. 주차 기준은 `inote-money`와 같다 — **달의 첫날이 속한 주가 1주차, 일요일 시작**. 기록 없는 주차는 만들지 않고, 달 이동은 **이번 달까지만**(다음 달 버튼 비활성). 기록 없는 달은 "이 달에는 기록이 없어요." (택하지 않은 안: "최근 7일/30일" 필터)
  - **전체 탭의 보기 방식(2026-10-12 추가)**: 전체 탭 아래에 **`[리스트 | 달력]` 선택**(처음은 리스트). **리스트** = 위에서 정한 최신순 카드 + [더 보기]. **달력** = `inote-money` 가계부 달력을 참고한 월 달력(일요일 시작, 일=빨강·토=파랑, 오늘 초록 원, `◀ 달 ▶` 이동은 이번 달까지). **기록이 있는 날 칸에만** "완료 M/N"(좁은 화면은 점: 모두 완료=초록, 남음=회색)을 찍고, 누르면 **그날 카드가 팝업**으로 열린다(체크 변경 가능, 입력줄 없음). 기록 없는 날은 누를 수 없다. 오늘은 기록이 달력에 안 나온다(오늘의 할일 탭에서 본다). 달력 데이터는 주차별·월별과 같은 한 달 조회(`from`+`before`)를 쓴다. (`inote-money`의 낭비·금액 표시는 해당 없음)
  - **확정(2026-10-12)**: 주소 `/todos/history`, 처음과 [더 보기] 한 번에 **7일 치**(기록이 있는 날만 세므로 빈 날은 건너뜀), 지난 카드에서도 **체크 변경 가능**(재확인함).
- 검토했다가 택하지 않은 안: 다음 날로 자동 이월("어제 못 한 일"), 이월하되 사용자가 [오늘로 옮기기]/[버리기] 선택.

### 5. 루틴은 매일만

- 주기 선택(요일 지정 등) 없이 항상 매일. 필요해지면 그때 추가한다(데이터 구조가 크게 안 바뀌는 방향으로).

### 6. "오늘의 할일" 카드 구성

- **카드 안에 텍스트 입력줄**이 있고, 입력하면 할 일이 추가된다. (페이지 위쪽의 별도 입력 폼은 두지 않는다)
- **입력줄은 오늘 카드에만 둔다.** 지난 기록 화면의 날짜 카드에는 입력줄이 없다.
- **지난 기록 화면의 카드에서도 체크박스를 바꿀 수 있다**(읽기 전용으로 두지 않음). 어제 깜빡하고 끝낸 걸 나중에 체크할 수 있다. 대신 완료 기록이 사후에 수정될 수 있다는 점은 감수한다(읽기 전용 안은 택하지 않음). ※ 지난 기록을 별도 화면으로 옮기기 전에 정한 결정이라, 그 화면에서도 같은지는 구현 전에 한 번 더 확인할 것.
- **각 항목 옆에 체크박스**로 완료를 체크한다. (지금 임시 화면의 원형 체크 버튼 대신)
- **루틴은 한 목록에 섞어서 보인다.** 루틴 항목에는 작은 "매일" 칩이 붙는다. (※ 결정 14: 이 칩과 자동 생성은 없어짐 — 고정 리스트에서 복사해 온 항목도 일반 항목)
- **루틴 등록**: ~~입력줄의 "매일 반복" 체크~~ → **2026-10-12 변경: 입력줄에서 "매일 반복" 체크를 뺀다.** 입력줄은 제목만 받아 그날 항목을 추가하고, **항목의 `⋯` 메뉴에서 [매일 반복으로 만들기]를 고르면** 그 항목이 오늘의 루틴 기록이 되고 내일부터 자동으로 나온다. (처음 결정한 입력줄 토글은 화면을 보고 사용자가 불필요하다고 해서 뺌)
- **`⋯` 메뉴 구성**(오늘 카드에서만): 그날 항목 → [매일 반복으로 만들기] / 루틴 → [이름 수정] [루틴 삭제]. 그날 항목의 이름 수정·삭제는 논의한 적 없어 메뉴에 넣지 않았다.
- 루틴 행에 붙는 작은 **"매일" 칩은 그대로 둔다**(어느 항목이 루틴인지 구분용 — "매일 반복 체크 표시가 필요 없다"는 말을 입력줄 체크로 이해함. 칩도 빼고 싶으면 알려줄 것).
- **루틴 수정·삭제는 행에서 바로 한다**(※ 결정 14로 폐지 — 카드에서는 [고정 리스트에 추가]만, 이름 수정·삭제는 설정 화면에서). 오늘 카드의 루틴 행에 마우스를 올리면(터치 기기는 항상 표시) `⋯` 메뉴가 나오고 [이름 수정] [루틴 삭제]를 고른다. 별도 관리 화면·패널은 두지 않는다.
- **지난 기록은 그대로 보존한다.** 루틴을 삭제하면 **오늘부터 안 나오고** 어제까지의 카드에는 남는다. 이름을 바꿔도 지난 카드는 그때 이름 그대로다. → 구현 시 **날짜별 기록에 그날의 이름을 함께 저장**해야 한다(루틴 이름만 참조하면 안 됨). 지난 카드에 남은 루틴 항목의 체크 변경은 가능(위 결정).
- 검토했다가 택하지 않은 안: 카드 안 소제목 분리("루틴"/"오늘 추가") + 헤더의 루틴 관리 버튼, 루틴을 설정 화면에서만 관리(→ 결정 14에서 결국 설정 화면 관리로 정리), 카드 헤더의 루틴 관리 패널, 수정·삭제를 모든 날짜에 반영.

### 7. 묶음 관리 ("할 일" 탭)

- **만들기**: 카드 목록 **맨 아래의 점선 "+ 새 묶음" 카드**를 누르면 이름 입력줄이 펼쳐진다(카드 안에서 끝남, 모달 없음). (페이지 위 [묶음 추가] 버튼 안은 택하지 않음)
- **이름 변경·삭제**: 묶음 카드 **헤더의 `⋯` 메뉴**에서 한다(루틴 행 메뉴와 같은 방식 — 사용자가 이 가정에 이의를 달지 않아 그대로 채택).
- **삭제 시 안의 작업은 함께 삭제한다.** 삭제를 누르면 "작업 N개도 함께 삭제됩니다" 확인 창이 뜨고, 확인하면 묶음과 작업이 같이 사라진다. (작업이 있으면 삭제를 막는 안, 작업을 다른 묶음으로 옮기는 안은 택하지 않음)

### 8. 작업 조작 ("할 일" 탭)

- **작업 추가**: 각 묶음 카드 **안의 입력줄**에서 한다. 입력줄은 **제목 + [일정 추가] 텍스트 버튼 + 추가**다(2026-10-12 변경: 날짜 입력칸 두 개 → 버튼). 버튼을 누르면 **달력 팝업**이 뜨고(결정 12), 고른 일정은 버튼 자리에 `10.20. ~ 10.25.`로 보이며 **"추가"를 눌러야 작업과 함께 저장**된다(추가 뒤엔 일정 선택이 비워짐). 안 고르면 일정 없이 추가된다. (일정을 사후에 메뉴에서만 지정하는 안은 택하지 않음)
- **상태 표시·변경** (2026-10-12 변경): ~~상태 아이콘(○ ◐ ●)~~ → **색상 뱃지**로 표시한다 — 할 일(회색) · 진행 중(파랑) · 완료(초록), 글자도 함께 보인다. **뱃지를 누르면 3개 상태 선택 메뉴**가 나오고 바로 고른다(할 일 → 완료로 바로 가도 한 번에 끝남). 색은 일단 정한 값이라 화면을 보고 조정할 수 있다.
- **순서 변경** (2026-10-12 추가): 작업 앞의 **손잡이(⠿)를 잡고 위아래로 끌어** 카드 안 순서를 바꾼다(키보드: 손잡이에서 Space → 방향키 → Space). **한 묶음 안에서만** — 다른 묶음으로 옮기는 건 포함하지 않는다. 순서는 **서버에 저장**되고, 자동 정렬(일정순 등)은 하지 않는다. 새 작업은 맨 뒤에 붙는다. (택하지 않은 안: `⋯` 메뉴의 위로/아래로)
- **이름 수정·일정 변경·삭제**: 작업 행의 **`⋯` 메뉴**에서 한다(루틴·묶음과 같은 방식 — 사용자가 이 가정에 이의를 달지 않아 그대로 채택).

#### "할 일" 탭 구현 세부 (2026-10-12, 결정 7·8·10을 화면으로 옮기며 정한 작은 것들 — 이의 있으면 바꾼다)

- **묶음 카드**: **처음엔 접혀 있고 이름 줄을 누르면 펼쳐진다**(결정 11). 이름 줄(펼침 표시·이름·별·완료/전체 개수·`⋯` [이름 변경] [삭제]) / **작업 한 목록**(상태 뱃지 + 제목 + 일정 칩, 손잡이) / 작업 입력줄 / 합계 줄. 완료된 작업도 같은 자리에 '완료' 뱃지로 남는다.
- **정렬**: 자동 정렬 없이 **사용자가 정한 순서**(처음엔 만든 순서). 서버에서 받은 순서가 곧 화면 순서다.
- **"오늘 일정" 영역**: 일정에 오늘이 드는 작업(시작일만이면 그날 하루, 기간이면 기간의 매일)을 **완료된 것까지** 모두 보여주고(취소선), 줄마다 묶음 이름 칩과 **묶음 카드와 같은 상태 메뉴·`⋯` 메뉴**가 있다. 없으면 영역 자체를 그리지 않는다. **일정이 지난 안 끝난 작업은 이 영역에 안 나온다**(오늘 일정만).
- **일정 변경**: 날짜 칩을 누르거나 `⋯` 메뉴의 [일정 변경]을 누르면 **달력 팝업**이 뜬다(결정 12). 일정이 없는 작업은 날짜 칩이 없어서 `⋯` 메뉴로만 들어간다 — 사용자가 "날짜가 없는 경우도 있으니 [일정 변경] 메뉴는 유지"라고 정함.
- **일정이 지난 작업**(안 끝난 것, 기준은 종료일·없으면 시작일)의 일정 칩은 **빨갛게** 보인다(옛 할일 페이지에 있던 표시를 그대로 가져옴).
- **삭제 확인 창**: **묶음 삭제만** 확인 창("'이름' 묶음과 작업 N개가 함께 삭제돼요")을 띄운다. 작업·루틴 삭제는 바로 지운다.
- **서버 응답 전(임시 id) 항목**은 상태·메뉴 조작을 막고, 임시 묶음에는 작업 입력줄도 막는다.

### 9. 기존 할일 데이터 처리

- 지금 `Todo` 테이블의 항목(제목·마감일·완료 여부)은 **"기존 할일"이라는 묶음 하나로 옮긴다.** "할 일" 탭에 그 묶음 카드가 생기고, 기존 항목은 그 안의 작업이 된다.
- **필드 매핑**: 제목 → 작업 제목 / 마감일 → **작업의 시작일**(종료일 없음 — 2026-10-12 결정 11 반영; 마감일의 뜻이 '그날 하루 일정'으로 바뀌는 점은 이전 때 사용자에게 한 번 더 확인) / 완료 여부 → 완료면 "완료", 아니면 "할 일"(진행 중은 없음). 사용자별로 항목이 있는 사람마다 묶음 하나를 만든다.
- 데이터를 잃지 않고, 쓰면서 다른 묶음으로 정리하거나(작업 이동 기능이 있다면) 지우면 된다. (택하지 않은 안: 새 테이블만 만들고 옛 데이터는 화면에 안 보이게 두기, 삭제하고 새로 시작)
- ⚠️ **구현 시 주의** (`inote/docs/handoff/HANDOFF.md` 5장): 로컬 BE와 운영 BE가 **같은 Supabase DB**를 쓴다. 이 이전은 **새 마이그레이션(추가만, `db push` 금지)** 으로, 옛 데이터를 새 구조로 복사하는 방식이어야 하고 옛 `Todo` 테이블은 바로 지우지 않는다. 마이그레이션 코드를 먼저 배포한 뒤 DB에 적용하는 순서를 지킨다(P3009 방지). 운영 DB의 항목 개수는 **아직 확인하지 않았다.**
- 미결정: 묶음 사이에서 작업을 옮기는 기능을 둘지(위 "기존 할일"을 정리하려면 필요) — 결정 7·8에는 없다.

### 10. 작업 일정은 "할 일" 탭에서 보여준다 (2026-10-12 변경)

- 처음에는 "일정이 오늘인 작업을 오늘의 할일 카드에도 보여주기"로 정했으나, **화면을 보고 사용자가 뒤집었다.** **"오늘의 할일"에는 오늘의 할일(루틴·그날 항목)만 나오고, 작업 일정은 나오지 않는다.** 지난 기록 카드에도 작업은 없다.
- **작업 일정은 "할 일" 탭 맨 위의 "오늘 일정" 영역**에서 본다: 일정이 오늘인 작업을 묶음과 상관없이 한데 모아 보여주고, 아래에 묶음 카드들이 나온다. 이 영역은 묶음 목록(`GET /task-groups`)에서 클라이언트가 계산하므로 **별도 API가 필요 없다.**
- 상태 뱃지와 상태 변경 메뉴는 묶음 안의 작업과 같은 동작이다(작업의 상태는 하나). 단 **순서 손잡이는 묶음 카드 안에만** 있고 "오늘 일정" 영역에는 없다.
- 택하지 않은 안: 묶음 카드 안의 날짜 칩으로만 표시(오늘 할 작업을 한눈에 모아 보기 어려움).
- 계약 영향: `DayCard`에서 `tasks`가 빠지고, 지난 기록 목록은 **항목이 있는 날만** 대상이다.

### 11. 묶음 접힘 · 중요(별) 표시 · 시작/종료일 (2026-10-12 추가)

- **묶음은 처음엔 접힌 목록**이다. 접힌 줄에는 **펼침 표시 · 이름 · 별 · 완료/전체 개수(예: `1/2`) · `⋯`** 만 있다. 이름 줄을 누르면 카드가 펼쳐지고(작업 목록·입력줄·합계 줄) 다시 누르면 접힌다. 묶음마다 따로 펼치고 접는다. **펼침 상태는 저장하지 않는다**(새로고침하면 다시 접힘). 새로 만든 묶음은 바로 펼쳐서 작업을 넣을 수 있게 한다.
- **중요(별) 표시**: 묶음 이름 옆과 **각 작업**에 별 토글이 있다(켜져 있으면 항상 보이고 꺼져 있으면 줄에 마우스를 올릴 때만). **표시만 하고 정렬·필터에는 영향을 주지 않는다**(직접 끌어서 정한 순서와 부딪히지 않게). 택하지 않은 안: 별 표시한 것을 위로 자동 정렬, "중요만 보기" 필터.
- **작업의 날짜는 시작일·종료일**이다. 허용 조합은 **없음 / 시작일만 / 시작일~종료일** 세 가지이고, **종료일만 있는 작업은 없다**(종료일은 시작일을 고른 뒤에만 고를 수 있고, 시작일을 지우면 종료일도 지워진다. 종료일은 시작일과 같거나 이후). 택하지 않은 안: 시작일·종료일을 완전히 따로 허용(종료일만도 가능).
- **"오늘 일정"에 드는 기준**: 시작일만 있으면 **시작일 당일에만**, 시작~종료면 **그 기간의 매일**(양 끝 포함). 일정이 없으면 안 나온다. (택하지 않은 안: 시작일만 있는 작업을 끝낼 때까지 계속 보여주기)
- **날짜 표시**: 시작일만이면 `10.20.`, 기간이면 `10.20. ~ 10.25.`.
- 계약 영향: `Task`에 `startDate`·`endDate`·`starred`(옛 `dueDate` 대신), `TaskGroup`에 `starred`가 생겼다.

### 12. "오늘 일정" 줄 모양 · 묶음으로 이동 · 달력 팝업 (2026-10-12 추가)

- **"오늘 일정" 줄 순서**: `상태 뱃지 | 묶음 이름 | 작업 제목 … 날짜 ★ ⋯`. 묶음 이름은 제목 **앞**에 붙는 작은 칩이다(예전엔 제목 뒤). 묶음 카드 안의 줄에는 묶음 이름이 없다(이미 그 묶음 안).
- **묶음 이름을 누르면** 아래 해당 묶음 카드로 **부드럽게 스크롤해서 이동하고, 접혀 있으면 펼친다**(이미 펼쳐져 있으면 접지 않고 이동만). 다른 묶음의 펼침 상태는 그대로.
- **날짜를 누르면 달력 팝업**: 날짜 칩(또는 `⋯`의 [일정 변경])을 누르면 **범위 선택 달력**이 뜬다. 고르는 방법:
  - **첫 클릭 = 시작일**(바로 하루 일정으로 저장되고 팝업은 종료일을 기다리며 열려 있음), **이어서 더 늦은 날 클릭 = 종료일**(기간으로 저장되고 닫힘), **같은 날을 한 번 더 클릭 = 하루 일정으로 확정**하고 닫힘, **더 이른 날 클릭 = 그날이 새 시작일**(계속 열려 있음). 이미 일정이 있는 작업에서 날짜를 누르면 예전 일정(종료일)은 버리고 새 시작일부터 고른다. **종료일만 있는 일정은 만들어지지 않는다.**
  - 팝업 안에 **안내 문구는 두지 않는다**(2026-10-12 사용자가 불필요하다고 정함 — 처음엔 "종료일을 누르면 기간이 돼요…" 문구가 있었음).
  - 팝업 아래에 **[일정 지우기]**(시작·종료 모두 없애고 닫음, 일정이 없으면 비활성)와 **[닫기]**(일정은 그대로 두고 닫음)가 있다. 날짜를 누를 때마다 바로 저장한다(낙관적, 실패하면 되돌리고 토스트).
  - 달력은 **한국어(월~일 요일 표시)**, 일정이 있는 작업은 그 일정이 있는 달로, 없으면 이번 달로 열린다.
- 택하지 않은 안: 브라우저 기본 달력(날짜 입력 두 칸 — 사용자 브라우저마다 모양이 다르고 달력이 두 번 뜸).
- 구현: 의존성 `react-day-picker`를 추가했다. 선택 규칙(`pickDate`)은 순수 함수로 분리해 테스트한다. **달력 팝업에서 날짜를 눌러 보는 동작은 jsdom에서도 테스트로 재현된다**(끌기와 달리) — 단 실제 브라우저에서의 모양·위치(팝업이 작업 줄 옆에 제대로 붙는지, 좁은 화면에서 잘리지 않는지)는 **사람이 화면에서 확인**해야 한다.

### 13. 모바일 작업 줄과 무한 스크롤 (2026-10-12)

- **작업 줄은 좁은 화면(`sm` 미만)에서 두 줄 카드형**: 윗줄 = 손잡이 · 상태 뱃지 · **제목(길면 줄바꿈, 끝에 별)** · ⋯ / 아랫줄 = 묶음 칩("오늘 일정"에서만) · 날짜 칩. 넓은 화면은 지금처럼 한 줄(칩 · 제목 · 날짜). (제목이 "할…"처럼 잘리던 문제 — 한 줄에서 제목만 줄이는 안 대신 택함)
- **무한 스크롤을 두 곳에 적용**: ① 지난 기록 > 전체 > 리스트(내리면 7일씩 자동으로 이어서 불러옴, 기존 [더 보기] 버튼 대체) ② "할 일" 탭의 묶음 목록(10개씩).
- ②는 **서버 계약을 바꾸지 않고 화면에서만 나눠 그린다**: `GET /task-groups`는 전체를 한 번에 주고, 화면이 10개씩 그린다. 이유 — "오늘 일정"이 전체 묶음의 작업을 모아 보여주고, 낙관적 업데이트·순서 변경이 한 목록을 기준으로 돌아가서, 서버 쪽 페이지 나누기를 하면 이 전체가 같이 바뀐다. 묶음이 수백 개가 되면 서버 페이지 나누기를 그때 계약에 추가한다. "오늘 일정"의 묶음 이름을 눌렀을 때 아직 안 그린 묶음이면 거기까지 그린 뒤 펼친다. 새 묶음을 만들면 전부 그린다.
- 끝 표시선이 화면에 닿는지는 `IntersectionObserver`로 보고(`shared/ui/load-more-sentinel`), 지원하지 않는 환경에서는 [더 보기] 버튼으로 대신한다.

### 14. 고정 리스트 = 복사해 오는 목록 (2026-10-12 변경 — 결정 1·5·6의 "루틴 자동 생성·연결"을 대체)

- **루틴이라는 개념을 없애고 "고정 리스트"로 바꾼다.** 고정 리스트는 매일 쓰는 할 일의 **원본 목록(템플릿)**일 뿐이고, **오늘 카드의 항목과 이어져 있지 않다.** 그래서 오늘 카드에 "매일" 칩도, 루틴 이름 수정·**루틴 삭제**(카드 메뉴)도 없다. (처음엔 [오늘 할일 생성] 버튼 방식이었다가 사용자가 버튼을 빼고 "그저 복사해서 가져오는 느낌"으로 바꿈)
- **설정 화면**(`/todos/settings`, 제목 "고정 리스트") — 진입: "할 일" 페이지 제목 줄 **오른쪽 끝의 아이콘+"설정" 버튼**.
  - 고정 항목 **추가**(입력줄) · **이름 수정** · **삭제**(`⋯` 메뉴, 삭제는 확인 창). 만든 순서대로, 순서 변경은 없다. 이름 수정·삭제는 **이미 가져온 오늘·지난 항목에 영향이 없다.**
  - **[오늘 카드에 모두 가져오기]** 버튼 하나: 누르면 고정 항목들의 **제목을 복사해 오늘 카드에 새 항목(체크 해제)으로 만들어 서버에 저장**하고 "오늘의 할일"로 이동한다. 오늘 카드에 **같은 제목이 이미 있으면 건너뛴다**(여러 번 눌러도 중복 없음). 항목별로 골라 가져오는 안은 택하지 않음.
- **자동 생성은 없다.** 오늘 카드는 열기만 해서는 아무것도 만들지 않는다(빈 카드면 "아직 항목이 없어요"). [오늘 할일 생성] 버튼도 없다. 가져오지 않은 날은 기록이 남지 않는다(이전에도 "앱을 안 연 날은 기록 없음").
- **오늘 카드 항목의 `⋯` 메뉴**(오늘 카드에서만)는 **[고정 리스트에 추가]** 하나 — 그 항목의 제목을 고정 리스트에 복사한다(카드의 항목은 그대로). 이전 [매일 반복으로 만들기]를 이 뜻으로 바꿨다.
- 가져온 항목은 직접 추가한 항목과 **같은 종류**의 일반 항목이다: 체크 가능, 다음 날로 이월 안 됨, 지난 기록에 그대로 남음.

### 디자인 방향 (이 의논에서 정리된 것)

- 사용자가 불편하다고 고른 것: **다른 화면과 톤이 안 맞음**, **목록 구성이 밋밋함**. 입력 방식은 불만이 아니었다(그래서 입력줄은 유지).
- 기준 화면은 **홈(글 목록)**. 홈과의 차이: 폭(`max-w-3xl` vs `max-w-2xl`), 헤더 아래 설명 줄, 섹션 소제목(`text-sm font-semibold text-zinc-500`), 행의 크기·메타 줄.
- 참고: 독서·홈·할일 모두 같은 회색(zinc) 계열이라 색은 차이가 아니다.

## API 계약 (2026-10-12 사용자 승인)

FE의 MSW 목데이터(`apps/web/src/mocks/todo/`)와 BE 구현의 기준이다. 날짜는 시간 없는 `YYYY-MM-DD`(한국 날짜), "오늘"도 한국 시간 기준(서버·브라우저 모두).

```ts
type TaskStatus = "TODO" | "IN_PROGRESS" | "DONE";

// 오늘의 할일 탭
type DailyEntry = { id; date; title; done }  // 그날 항목 — 직접 추가한 것도, 고정 리스트에서 복사해 온 것도 같은 종류(서로 이어져 있지 않다)
type DayCard    = { date; entries: DailyEntry[] }

// 할 일 탭
type Task      = { id; groupId; title; status: TaskStatus; startDate: string | null; endDate: string | null; starred: boolean }
type TaskGroup = { id; name; starred: boolean; tasks: Task[] }
// 일정 규칙: 없음 / 시작일만 / 시작일~종료일. 종료일만 있는 작업은 없고(endDate가 있으면 startDate도 있다), endDate >= startDate
```

| 화면 | 엔드포인트 | 설명 |
|---|---|---|
| 오늘 카드 | `GET /daily/:date` → `DayCard` | **읽기만 한다** — 기록이 없으면 `entries: []`. 열었다고 항목을 만들지 않는다 |
| 고정 리스트 가져오기 | `POST /daily/from-routines` → `DayCard`(오늘) | 고정 리스트의 **제목을 복사해 오늘 카드에 새 항목(체크 해제)으로 저장**. 오늘 카드에 **같은 제목이 이미 있으면 건너뜀**(여러 번 호출해도 중복 없음). 고정 리스트가 비면 오늘 카드를 그대로 돌려줌. 오늘만 가능 |
| 지난 기록 | `GET /daily?before=날짜&limit=&from=날짜` → `{ items: DayCard[], nextBefore }` | 항목이 있는 날만, 최신순. `before`는 미포함·`from`은 포함(선택) — 전체 탭은 `before`+`limit`으로 [더 보기], 주차별·월별은 `from=그달1일&before=다음달1일&limit=31`로 한 달 치를 한 번에. **오늘 이후는 항상 제외**(오늘은 `GET /daily/:date`) |
| 항목 추가 | `POST /daily/entries` `{ title }` | 그날 항목 추가. **오늘만 가능** |
| 고정 리스트 | `GET /routines` → `{ id, title }[]` | 만든 순서 |
| 고정 항목 추가 | `POST /routines` `{ title }` → `{ id, title }` | 설정 화면 입력줄, 또는 오늘 카드 항목 메뉴 [고정 리스트에 추가](그 항목의 제목을 보냄). **오늘 카드에는 넣지 않는다** |
| 체크·이름 | `PATCH /daily/entries/:id` `{ done?, title? }` | 지난 날짜도 체크 가능 |
| 고정 항목 수정·삭제 | `PATCH /routines/:id` `{ title }` / `DELETE /routines/:id` | 고정 리스트만 바뀐다. **이미 가져온 오늘·지난 카드의 항목은 그대로**(복사본이라) |
| 묶음 | `GET/POST /task-groups`, `PATCH/DELETE /task-groups/:id` | `GET`은 묶음마다 작업을 **저장된 순서대로** 함께 준다(처음엔 만든 순서, 새 작업은 맨 뒤). `PATCH`: `{ name?, starred? }`. 이름은 1~50자. 삭제하면 안의 작업도 함께 삭제 |
| 작업 순서 | `PUT /task-groups/:id/tasks/order` `{ taskIds: string[] }` → 204 | 그 묶음 작업 **전체**를 원하는 순서로 한 번씩 보낸다(모자라거나 겹치거나 다른 묶음 것이 섞이면 400). `GET /task-groups`의 작업 순서가 이 순서다 |
| 작업 | `POST /task-groups/:id/tasks` `{ title, startDate?, endDate? }`, `PATCH/DELETE /tasks/:id` | 제목 1~200자, 새 작업은 `TODO`·별 없음. `PATCH`: `{ title?, startDate? (null이면 해제), endDate? (null이면 해제), status?, starred? }`. 날짜는 `YYYY-MM-DD`. **일정 규칙에 어긋나면 400**(종료일만 있음, 종료일 < 시작일, 시작일만 지우고 종료일을 남김 — 시작일을 지울 때는 `endDate: null`도 함께 보낸다) |

- **알려진 선택**: 날짜별 기록은 사용자가 항목을 직접 추가하거나 [오늘 카드에 모두 가져오기]를 눌러야 생긴다(별도 스케줄러·GET 부작용 없음). **아무것도 안 한 날은 지난 기록에 안 남는다.** 루틴 연결(`routineId`)·"매일" 칩은 없다.
- 그날 추가 항목의 **삭제**는 계약에 넣지 않았다(논의한 적 없음). 필요하면 `DELETE /daily/entries/:id`를 추가한다.
- 기존 `/todos` 평면 API는 BE가 새 구조로 옮겨질 때까지 그대로 둔다.
